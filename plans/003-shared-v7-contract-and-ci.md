# Plan: Add a Shared v7 Contract and Ecosystem CI

## Problem

The v7 record contract is repeated in several places:

- `/Users/mantas/Git/uncwo/cstate/data/record_sections.yml`
- `/Users/mantas/Git/uncwo/cstate/exampleSite/static/admin/config.yml`
- `/Users/mantas/Git/uncwo/cstate/exampleSite/static/admin/index.html`
- `/Users/mantas/Git/uncwo/cstate-extra/cstate-cli/lib/recordTypes.js`
- `/Users/mantas/Git/uncwo/cstate-extra/monitorbot/utils/incidentManager.js`
- `/Users/mantas/Git/uncwo/cstate-extra/html-embed/scripts/verify-v7-api.mjs`

Each repo has some local verification, but there is no shared fixture or schema that says what cState v7 means across the ecosystem. This makes future changes risky: a field can be added to the theme and missed by CLI, MonitorBot, or embeds.

The theme now has `/Users/mantas/Git/uncwo/cstate/.github/workflows/release-checks.yml`, but the sister repos do not currently show GitHub workflow coverage in this checkout.

## Proposed implementation

1. Create a versioned v7 API fixture in the theme, for example `test/fixtures/index-v2.1.json`.
2. Add a small JSON Schema or documented fixture contract for:
   - `summaryStatus`
   - `records`
   - `recordType`
   - `kind`
   - `state`
   - `severity`
   - `statusImpact`
   - `pin`
   - `systems[].experimentStatus`
   - `systems[].runningExperimentCount`
   - `systems[].experiments`
3. Reuse that fixture in html-embed tests instead of maintaining a separate hand-shaped payload.
4. Add CI workflows to cstate-cli, monitorbot, and html-embed that run their existing `npm test` commands.
5. Add one ecosystem compatibility check that builds the cState example site and validates at least one generated experiment record through each consumer.

## Acceptance criteria

- Changing the v7 record contract in the theme breaks at least one test unless the consumers are updated.
- html-embed tests load a fixture generated by cState or copied from the shared contract.
- cstate-cli and monitorbot CI run on `v7` branches and pull requests.
- The theme release check remains independent and fast.

## Risk

Low technical risk, high leverage. This is the main guardrail against v7 becoming five almost-compatible products.
